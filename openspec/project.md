# Project Context

## Purpose

Herald is the single-responsibility notification service for Leo's agent fleet. It owns
every attention channel: spoken TTS (Kokoro synthesis on the homelab, ssh/afplay playback
on the Mac), Moshi mobile hook wiring (iPhone/Watch inbox, Live Activities, approvals),
per-attempt notification history, and the `/notify` control surface. Harnesses (claude/cc,
codex, pi) consume herald as a plugin; no harness carries its own speech or push logic.

## Tech Stack

- **Shell**: bash entry points (`bin/notify.sh`, `bin/kokoro-sync.sh`) — fail-soft, exit 0,
  bounded timeouts
- **Go**: `pkg/notify` (voice resolution, Kokoro HTTP client, NDJSON history store) built
  into a `herald` binary
- **Synthesis**: Kokoro-FastAPI (`ghcr.io/remsky/kokoro-fastapi-cpu`), Docker compose module
  installed on the homelab by `kokoro-sync.sh`
- **Transport**: Tailscale ssh mesh; playback via `afplay` on the Mac
- **Mobile**: Moshi (getmoshi.app) via the `moshi-hook` binary on harness hook events
- **Distribution**: CC plugin (`plugin/` with `.claude-plugin/plugin.json`), plus codex
  `hooks.json` and pi extension wiring documented in `docs/`

## Conventions

- Provider-qualified voices: `kokoro:af_heart`; a bare voice string is legacy ElevenLabs.
- Every notify attempt appends one history record, delivered or not.
- Compose modules in-repo are source of truth; host copies are generated by sync scripts.
- No hardcoded host addresses in Go; env/config with one documented default location.
- OpenSpec workflow identical to `~/dev/cc`: `openspec/changes/<slug>/` with proposal.md,
  tasks.md, and spec deltas; archive on completion; specs in `openspec/specs/`.
